# RetroVault

**電玩／動漫迷的收藏基地**——單一網頁運作的 PWA（Progressive Web App）收藏管理工具，專為電玩、動漫周邊的實體與數位收藏設計。

**線上使用**：<https://kevinte67228.github.io/Retro-library/>（直接開啟即可，也可以「加到主畫面」當原生 App 使用）

**完整使用手冊**：[manual.html](./manual.html)（含 Google 帳號設定教學、各功能詳細操作說明、常見問題）

---

## 這是什麼

RetroVault 是給收藏玩家用的個人資料庫工具，核心理念是：

> **資料完全歸你所有**——App 本身只是操作介面，不經過任何第三方伺服器儲存你的資料。所有收藏記錄存在**你自己的 Google 試算表**裡，照片存在**你自己的 Google Drive**裡。

這代表：
- 不需要註冊帳號、不需要信任第三方保管你的收藏資料
- 你隨時可以打開自己的 Google 試算表，直接檢視或編輯原始資料
- 前後端原始碼完全公開，想確認資料流向、自行檢查邏輯都可以

## 能管理哪些收藏

**8 大分類**：遊戲、書籍／攻略、主機、週邊、原聲帶、動漫／美術設定集、公仔／模型、數位下載版，另有獨立的**尋寶清單**追蹤還沒入手、正在比價中的目標商品。

原聲帶、動漫／美術設定集、公仔、數位下載版這 4 個分類還有各自的**子類型細分**（例如公仔分比例模型／可動模型／黏土人等 6 種），每個子類型有量身設計的專屬欄位。

## 核心功能

### 8 種建檔方式
- **商品條碼／商品編碼**：掃描或輸入條碼／序號，自動查詢多個資料庫（樂天市場、ScreenScraper、openBD、NDL 國會圖書館等）帶入商品資訊
- **圖片辨識**：拍攝或上傳封面照片，AI（Google Gemini）自動辨識商品並填寫欄位
- **條碼＋照片／編碼＋照片**：結合資料庫查詢與 AI 圖片辨識，精確度最高
- **手動建檔**：直接手動填寫，也可以用「搜尋資料庫帶入」輔助功能查詢 IGDB 候選清單快速帶入
- **AI 網頁查詢**：產生查詢提示詞，複製貼到你慣用的 AI 網頁助手（Gemini／ChatGPT／Claude／DeepSeek）查詢，再把回覆貼回來自動匯入
- **批次書背**：一次拍多張書背照片，AI 辨識＋資料庫查詢，批次確認後一次寫入收藏

### 收藏管理
- 卡片／分類／畫廊三種瀏覽模式，多條件篩選與排序
- 詳細頁支援關聯商品（同系列/同款商品互相連結）、多圖燈箱瀏覽
- 批次編輯：依選取項目的分類動態顯示對應可修改欄位（保管位置、收藏狀態、品項完整度等）
- CSV 匯出／匯入，方便备份或跟其他工具交換資料

### 估值與統計
- 估值工作台：自動搜尋二手市場（Mercari、日本樂天、ヤフオク、Buyee 等，可自訂常用查價網站）抓取參考價格
- 統計儀表板：收藏數量、購入成本、估值趨勢、平台分布、品相評級等視覺化圖表

### 尋寶清單
獨立的「還沒入手」追蹤清單，記錄目標商品的比價資訊（多個通路報價、看到日期），達到心理價位時提示，找到後可一鍵轉入正式收藏。

## 技術架構

```
前端（PWA，共用）              後端（每人各自獨立）
┌─────────────────┐          ┌──────────────────────────┐
│  index.html      │  HTTP    │  Google Apps Script       │
│  單一檔案前端     │ ───────▶ │  （橋樑，處理讀寫邏輯）    │
│  離線快取 (PWA)   │          └──────────────┬───────────┘
└─────────────────┘                           │
                                    ┌──────────┴──────────┐
                                    ▼                     ▼
                          Google 試算表           Google Drive
                          （收藏資料庫）           （照片儲存）
```

- **前端**：純前端單一 HTML 檔案（無框架，原生 JavaScript），所有人共用同一份部署，透過 Service Worker 支援離線瀏覽
- **後端**：Google Apps Script 作為橋樑，每個使用者各自部署一份、綁定自己的 Google 試算表——這是資料獨立/私密的關鍵設計
- **AI 辨識**：呼叫 Google Gemini 多模態 API（使用者自己申請免費金鑰，存在自己瀏覽器本機，不經過任何中介伺服器）
- **跨源資料查詢**：視分類自動比對 IGDB、ScreenScraper、樂天市場／樂天Books、openBD、NDL 國會圖書館、RAWG 等多個公開資料庫

## 開始使用

1. 打開 <https://kevinte67228.github.io/Retro-library/>
2. App「設定」頁的「首次設定向導」會引導你花約 5 分鐘建立自己的資料庫後端（建立 Google 試算表 → 開啟 Apps Script → 貼入後端程式碼 → 部署 → 把網址填回設定頁）
3. 完成後即可開始建檔，資料全部存在你自己的 Google 帳號

詳細步驟、AI 金鑰申請、各功能操作說明，請見**[完整使用手冊](./manual.html)**。

## 這個資料夾（`docs/`）是什麼

這是 GitHub Pages 的部署根目錄，設定為「Deploy from a branch → main → /docs」，這個資料夾底下的檔案有任何變動，GitHub Pages 會自動重新建置上線。

| 檔案 | 用途 |
|---|---|
| `index.html` | 前端主程式（單一檔案 PWA） |
| `RetroVault_AppsScript.gs` | 後端原始碼，可從 App 內「設定」頁下載，貼進自己的 Apps Script 專案 |
| `appsscript.json` | Apps Script 專案設定檔 |
| `manifest.json` | PWA 安裝設定（名稱、圖示、啟動模式） |
| `sw.js` | Service Worker，處理離線快取 |
| `manual.html` | 使用手冊 |
| `gallery.html` | 功能截圖畫廊 |
| `icons/` | App 圖示與市場平台小圖示 |
| `Photo/` | 使用手冊撰寫用的截圖素材 |

版本號顯示在 App 左上角（例如 `v03.10`），對應的版本化 HTML 快照（`RetroVault_vXX_YY_index.html`）也放在這個資料夾，供版本回溯使用。

`_internal/`（repo 根目錄下）存放開發用的內部文件、部署腳本與版本備份，不在這個公開部署範圍內。
