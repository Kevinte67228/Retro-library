**修正：從收藏頁進入編輯、按「取消」後會停在建檔頁，而不是回到收藏頁**（使用者回報）。

根本原因：`editDetail()` 是把既有記錄的資料倒進全域 `entry`、然後 `showPg('scan')` 切到建檔頁去共用同一份編輯表單。但取消鈕綁的是通用的 `resetAll()`，這個函式的職責只有「把建檔頁重設成乾淨的起始狀態」，它不知道使用者是從收藏頁進來的，也就不會切回去——所以取消之後人就留在建檔頁了。

**修正 v02.105 引入的收藏頁工具列排版錯位**（使用者回報，附截圖）。

根本原因：`#pg-col .col-tools` 是 CSS grid，欄位定義寫死成「搜尋框 + 3 顆按鈕」（`minmax(0,1fr) 44px 44px 44px`）。v02.105 新增了第 4 顆按鈕（拍照 OCR 比對收藏）後，工具列實際有 5 個 grid 項目、但只宣告了 4 欄，第 5 個項目（篩選按鈕）因此溢位到隱含的第二列，並且套用到第一欄的 `1fr` 寬度，變成一顆超寬的按鈕孤零零卡在下面一整列——這就是截圖裡看到的錯位。這是「新增按鈕時忘記同步改 grid 欄數」造成的，不是樣式微調問題。

修正：把 grid 欄數補成 5 欄（搜尋框 + 4 顆按鈕），四顆按鈕正確回到同一列對齊。窄螢幕斷點（≤430px）的按鈕從 42px 縮成 40px、間距從 8px 縮成 7px，確保多一顆按鈕後搜尋框仍有足夠寬度；同時把該斷點的按鈕高度從 42px 改成 40px，維持按鈕是正方形（原本高度沒有跟著寬度一起調，會變成長方形）。已在 CSS 加註解說明「日後增減這排按鈕時，grid 欄數必須一起改」，避免同樣的問題再發生一次。
